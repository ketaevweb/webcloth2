# WebCloth 2

**Высокопроизводительный аналог Magica Cloth 2 для WebGPU / WebGL 2+ — физика ткани прямо в браузере.**

WebCloth 2 — оригинальная открытая реализация вершинной симуляции ткани на базе **XPBD**
(Extended Position Based Dynamics) с **compute-шейдерами WebGPU** и оптимизированным
**CPU-фолбэком для WebGL 2+**. Движок не зависит от фреймворков и легко подключается
к three.js, Babylon.js или собственному рендереру.

> Проект не связан с MagicaSoft и не содержит кода Magica Cloth 2 — это самостоятельная
> реализация публично известных методик (PBD/XPBD, аэродинамика по треугольникам).

## Демо

**Живая демонстрация:** https://ketaevweb.github.io/webcloth2/

В демо четыре сцены:

| Сцена | Что показывает |
|---|---|
| **Флаг** | Большое полотнище на мачте: аэродинамика ветра, турбулентность, порывы |
| **Персонаж** | Юбка на бегущем манекене: кинематический пояс, коллайдеры-капсулы на конечностях, инерция движения |
| **Кости** | Bone Cloth: хвост на скелетной цепи со скиннингом (SkinnedMesh) и две косы-капсулы, всё сталкивается с телом |
| **Стресс-тест** | 1–24 независимых полотнища, счётчики частиц/связей, FPS — честное сравнение бэкендов |

Все параметры физики (ветер, гравитация, жёсткость, изгибы, трение, подшаги, итерации)
меняются на ходу; переключение бэкенда WebGPU ⇄ CPU — одной кнопкой.

## Возможности

- **GPU-вычисления (WebGPU)** — весь XPBD-пайплайн в WGSL: интеграция, решение связей,
  самоколлизии, коллизии, обновление скоростей. Пул частиц и связей — один буфер, ноль копирований на подшаг.
- **CPU-бэкенд (WebGL 2+ / fallback)** — решатель на типизированных массивах (SoA),
  ноль аллокаций в кадре, ~10–40 тыс. частиц в реальном времени на десктопе.
- **Структурные + изгибные связи** — дистанционные XPBD-связи по рёбрам сетки и между
  противоположными вершинами смежных треугольников.
- **Аэродинамический ветер** — сила считается по треугольникам (нормаль × площадь ×
  относительный поток) с многооктавным value-noise турбулентностью и порывами.
- **Коллайдеры** — сферы, капсулы, плоскости; анимация каждый кадр; тангенциальное трение.
- **Кинематические привязки** — внешне управляемые вершины (пояс юбки, петли) с корректной
  скоростью для аэродинамики.
- **Bone Cloth (костная ткань)** — XPBD-цепочки костей (Magica-стиль): корень управляется
  скелетом, суставы решаются с изгибной жёсткостью, коллайдерами и ветром; трансформы
  костей гонят скиннинг (THREE.Bone / SkinnedMesh) или сегментную визуализацию.
- **Самоколлизии** — spatial hash по частицам (радиус = 0.45 × шаг сетки ткани): складки
  не слипаются, отдельные полотнища расталкиваются. Работает и на CPU (counting sort),
  и на WebGPU (uniform grid фиксированной ёмкости с атомиками).
- **Разрывы ткани** — структурные связи рвутся при растяжении rest × «Прочность»;
  зависимые изгибные связи каскадно отключаются, треугольники удаляются из рендера;
  флаги разрывов читаются обратно с GPU. Сброс восстанавливает полотно целиком.
- **Сварка вершин** — дубликаты UV-швов склеиваются, ткань не рвётся по швам.
- **Watchdog** — NaN-коррупция GPU-вывода автоматически переключает бэкенд на CPU.

### Использование движка

```ts
import * as THREE from "three";
import { ClothEngine } from "@/lib/cloth";

// 1. Создать движок (async: определяет WebGPU)
const engine = await ClothEngine.create();
engine.settings.windStrength = 9;         // живые настройки
engine.settings.substeps = 2;
engine.settings.iterations = 8;

// 2. Добавить ткань из любой THREE.BufferGeometry
const flag = new THREE.PlaneGeometry(2.6, 1.6, 40, 24);
flag.translate(1.3, 0, 0);
const cloth = engine.addCloth(flag, {
  pinnedPredicate: (x) => x < 0.05,       // закреплённая кромка
  // kinematicPredicate: (x, y, z) => ... // внешне управляемые вершины
});

// 3. Коллайдеры
engine.addCollider({ kind: "capsule", ax:0, ay:1, az:0, bx:0, by:1.6, bz:0,
                     radius: 0.12, nx:0, ny:1, nz:0 });

// 4. Каждый кадр
function frame(dt: number) {
  cloth.updateKinematicTargets((rx, ry, rz, out, i) => {
    out[i] = rx; out[i + 1] = ry; out[i + 2] = rz; // трансформация пояса
  });
  await engine.update(dt);                 // физика + синхронизация геометрии
  renderer.render(scene, camera);
}
```

## Архитектура

```
src/lib/cloth/
├── ClothBuilder.ts   геометрия → симуляционная сетка (сварка, связи, смежность)
├── CpuSolver.ts      XPBD-решатель на CPU (SoA, без аллокаций)
├── WebGpuSolver.ts   WebGPU compute-оркестратор (буферы, диспетчи, readback)
├── shaders.ts        WGSL: integrate / solve / collide / updateVelocity
├── ClothEngine.ts    фасад: пул частиц, бэкенды, кинематика, синхронизация
├── noise.ts          value-noise (зеркалится в WGSL)
└── types.ts          настройки, коллайдеры, статистика
```

Пайплайн подшага (× substeps за кадр):

```
integrate → (solve × iterations) → collide → updateVelocity
```

## Производительность

Замеры в демо (скорость видна в HUD):

- **WebGPU**: десятки тысяч частиц и сотни тысяч связей при 60 FPS (лимит — readback).
- **CPU**: ~10–20 тыс. частиц при 60 FPS на современном десктопе.

Советы: для слабых устройств снижайте `substeps`/`iterations`; при мягкой ткани
уменьшайте `distanceStiffness`; ветер действует сильнее при большем `aeroDrag`.

## Дорожная карта

- WebGL2 GPU-путь (transform feedback)
- Экспорт в npm-пакет
- Самоколлизии: параллельный префикс-сумм на GPU вместо фиксированной ёмкости ячеек
- Разрывы: порог по площади треугольника и клей / починка связей

## Устранение неполадок

**Единственный правильный адрес демонстрации:**
https://ketaevweb.github.io/webcloth2/

| Симптом | Причина и решение |
|---|---|
| Ссылка ведёт на `zai-webcloth.github.io` и даёт 404 | Это устаревшая ссылка из ранних версий README — актуальный адрес только `ketaevweb.github.io/webcloth2/` |
| Демо открылось, но ткани не видно / сцена «старая» | Браузер или CDN закэшировал прошлую сборку. GitHub Pages кэширует до 10 минут — сделайте жёсткое обновление **Ctrl+F5** (Windows/Linux) или **Cmd+Shift+R** (macOS). В левом HUD есть строка «сборка …» — сверьте её с последним коммитом в ветке `gh-pages` |
| Бейдж «WebGPU недоступен», кнопка WebGPU неактивна | В браузере нет WebGPU (Firefox/Safari до недавних версий, некоторые Linux-сборки). Движок сам работает на CPU-бэкенде — всё то же самое, чуть медленнее |
| Ткань дёрнулась и замерла после переключения бэкенда | Исправлено в v2.0.1: гонка readback при пересоздании GPU-буферов больше не сбрасывает симуляцию |
| Чёрный экран и сообщение «Демо не смогло запуститься» | WebGL 2 заблокирован (обычно отключено аппаратное ускорение). Включите его в настройках браузера либо откройте демо в Chrome/Edge/Firefox 125+ |
| Низкий FPS | Снизьте «Подшаги» и «Итерации» в панели физики, уменьшите число полотнищ в стресс-сцене |
